# Phase 9 — Retrain lifecycle

After cutover, the local model lives on as `aula:v1` in Ollama. Improvement comes from periodic retrains using accumulated B3 captures (Phase 1) + fresh B1 replays (Phase 2) against the most recent N months.

## Cadence

**Monthly** for the first six months — enough new data accumulates to be worth a retrain, schedules and posts shift across school terms. After six months, drop to **quarterly** unless E4 canary trips.

## What changes per retrain

1. **Data**: rerun Phase 2 historical replay against the last ~2 months (the fresh window). Concatenate with the older training set.
2. **Manual additions**: any held-out failure examples from E3 shadow week or production hiccups (Phase 8 emergency fires) get added by hand as "high-priority" examples — see below.
3. **LoRA**: retrain from scratch on the combined dataset using `4-finetune/train.sh`. Don't continue-train; start fresh per release.
4. **Eval**: re-run E1 + E2 strictly. E3 shadow can be condensed to 2-3 days for subsequent releases (you know the failure modes by now).
5. **Tag**: register as `aula:v2`, `aula:v3`, … in Ollama. Don't overwrite the previous tag.
6. **A/B**: run E2 against both `aula:vN` (current prod) and `aula:vN+1` on the same 30 held-out examples. Promote only if new model wins ≥ 3:1 on margin or is strictly equivalent.

## Versioning + rollback

Ollama tags are cheap. Keep the last 3 production versions resident:

```bash
ollama list | grep aula
# aula:v1  (2026-06)
# aula:v2  (2026-07)
# aula:v3  (2026-08)  ← current
```

Rollback is a single HA setting flip + `ollama pull aula:vN` if you'd already cleaned the old tag. The E4 canary automation does this automatically on degradation triggers (Phase 7).

## Manual edge-case corpus

Each time a failure makes it past the validator and reaches Telegram badly (or each time the emergency template fires unexpectedly), append a hand-corrected (prompt, gold_response) pair to `~/aula-train/manual/edge-cases.jsonl`. Phase 3 `prepare.py` will include it on the next retrain.

Format (same as Phase 2 output, minus `tool_calls`):

```json
{
  "conv_id": "manual-2026-07-12-anna-cancelled",
  "kind": "weekday",
  "ts": "2026-07-12T07:30:00+02:00",
  "prompt": "...the full assembled prompt that ran that morning...",
  "response": "...the corrected Danish notification you wish the model had emitted...",
  "tool_calls": [ ... copy from the matching trace-2026-07-12.jsonl ... ]
}
```

These get weighted 2-3× in `prepare.py` (passes `--weight-manual 3` to repeat them in the training set). The `--weight-manual` flag isn't shown in the Phase 3 example but is a simple addition — see [cutover-checklist.md](./cutover-checklist.md).

## Reading the canary

`input_number.aula_local_pass_rate` is your retraining signal:

- ≥ 0.97 — local model is fine. Retrain monthly for freshness only.
- 0.93-0.97 — drift detected. Retrain on schedule; investigate which examples failed.
- < 0.93 — material regression. Retrain immediately or roll back. E4 will trip at 0.90.

## What to NOT retrain on

- Failed runs (`ok: false` tool calls).
- Runs where the response was generated by the emergency template (these are degraded, not gold).
- Runs from shadow week where the Ollama side was wrong (use the Gemini gold from those days).

`prepare.py` already drops the first two; the third is on you.
